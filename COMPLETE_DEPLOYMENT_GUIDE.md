## 📋 OVERVIEW

This guide covers deploying your full-stack application:
- **Frontend** → Vercel

- Has correct DATABASE_URL format
- Has all environment variables

**frontend/.env.local** ✅
- Has VITE_SUPABASE_URL
- Has VITE_SUPABASE_PUBLISHABLE_KEY

**dashboard/.env.local** ✅

## PART 2: DEPLOY BACKEND ON RENDER

### Step 2.1: Create Render Account
1. Go to https://render.com
2. Sign up (use GitHub account for easier linking)
3. Create account and verify email

### Step 2.2: Deploy Using Blueprint

1. Go to https://render.com/dashboard
2. Click **"Create"** (top right)
3. Select **"Blueprint"**
4. Select **"GitHub"**
5. Authorize GitHub if needed
6. Select repository: `guides-nepal`
7. Click **"Connect"**

### Step 2.3: Configure Blueprint

1. You'll see render.yaml preview
2. Look for these values:
   ```yaml
   services:
     - name: guides-nepal-backend
       envVars:
         - key: DATABASE_URL
           value: postgresql://postgres:Guidesnepal%40123@db.wuyxvqkokyhjbfzemjyw.supabase.co:5432/postgres
   ```

3. If DATABASE_URL shows `***`:
   - Click **"Edit"**
   - Paste correct value:
     ```
     postgresql://postgres:Guidesnepal%40123@db.wuyxvqkokyhjbfzemjyw.supabase.co:5432/postgres
     ```
   - **IMPORTANT**: `@` in password must be `%40`

4. Check these are set:
   - [ ] DATABASE_URL (with %40 for @)
   - [ ] ENV = production
   - [ ] SECRET_KEY = generateValue: true
   - [ ] BACKEND_CORS_ORIGINS = correct Vercel URLs (or leave for now)

5. Click **"Deploy"**

### Step 2.4: Wait for Deployment

1. Watch the logs
2. Takes 5-10 minutes usually
3. Succeeds when status shows **"Live"**

### Step 2.5: Get Backend URL

1. Click the deployed service
2. Copy the URL (e.g., `https://guides-nepal-backend.onrender.com`)
3. **SAVE THIS** - you'll need it for frontend

### Step 2.6: Test Backend

```bash
# Test health endpoint
curl https://guides-nepal-backend.onrender.com/health

# Should return:
# {"status":"ok","environment":"production"}
```

✅ Backend is deployed!

## 🆘 TROUBLESHOOTING

### Backend won't deploy
1. Check Render logs for error
2. Check DATABASE_URL has `%40` for `@`
3. Check requirements.txt doesn't have `cors`
4. See RENDER_DEPLOYMENT_TROUBLESHOOTING.md

### Frontend shows blank page
1. Check Vercel logs
2. Check environment variables are set
3. Check VITE_API_URL is correct
4. Open browser console - see any errors?

### CORS errors in frontend
1. Check BACKEND_CORS_ORIGINS on Render
2. Check it includes correct Vercel URLs
3. Restart backend (Render dashboard → Restart)
4. Wait 2-3 minutes

### Backend returns 502 error
1. Wait 2 minutes (might still be starting)
2. Test health endpoint: `curl https://guides-nepal-backend.onrender.com/health`
3. Check Render logs for errors
4. Try restarting: Render dashboard → Restart

### Can't connect to Supabase
1. Check DATABASE_URL format
2. Test locally first:
   ```bash
   export DATABASE_URL="postgresql://postgres:Guidesnepal%40123@db.wuyxvqkokyhjbfzemjyw.supabase.co:5432/postgres"
   python -c "from sqlalchemy import create_engine; engine = create_engine('$DATABASE_URL'); print('✅ Connected')"
   ```
3. If fails, check password and URL format

## 🔐 SECURITY REMINDER

### Production Security Checklist
- [ ] SECRET_KEY is generated (not default)
- [ ] DATABASE_URL is secure (not in source code)
- [ ] HTTPS is enforced (use https:// URLs)
- [ ] CORS is whitelist-only (no wildcards)
- [ ] API keys not exposed in frontend
- [ ] Environment variables not logged
- [ ] Rate limiting enabled (slowapi)
- [ ] Input validation enforced
- [ ] SQL injection prevention (SQLAlchemy ORM)
- [ ] XSS prevention (input sanitization)
